## Реализовано

- `POST /api/retake-requests` создаёт заявку со статусом `New`, id и порядковым номером.
- `GET /api/retake-requests` возвращает список (пустой список — `200 []`); `GET /{id}` возвращает `404`, если записи нет.
- Два отдельных PATCH: назначение исполнителя и смена статуса.
- Проверяются поля создания: title 5–80 символов, description 10–500 символов, disciplineId больше нуля.
- Переход в `InProgress` требует исполнителя, даты, времени и аудитории; статус меняет только назначенный пользователь.
- Некорректные данные дают `400`, отсутствующая запись — `404`, запрещённый переход — `409`.
- Неожиданная ошибка логируется одной структурированной строкой без тела запроса и возвращается безопасным `ProblemDetails` с кодом `500`.
- Данные хранятся в памяти и исчезают при перезапуске.

## Проверки

Коллекция для повторения запросов: [`docs/api-collection/retake-requests.postman_collection.json`](../api-collection/retake-requests.postman_collection.json). Запросы в ней запускаются последовательно; PATCH использует учебный заголовок `X-User-Id`.

| Сценарий | Ожидаемый результат |
|---|---:|
| Создание корректной заявки | 201, `id`, `number`, `status: New` |
| Создание с коротким title | 400 |
| GET несуществующего id | 404 |
| InProgress до назначения исполнителя | 409 |
| Назначение, установка расписания, InProgress и Closed | 200 |

## Доказательство безопасного лога

Исключение временно вызывалось после успешной валидации запроса создания и затем было удалено. Сервер записал:

```text
Unhandled request failed; method=POST; path=/api/retake-requests; error=InvalidOperationException
```

Клиент получил только `500 application/problem+json` с заголовком «Не удалось обработать запрос»; стек и абсолютные пути в ответ не включались. Искусственный сбой в исходниках не оставлен.
